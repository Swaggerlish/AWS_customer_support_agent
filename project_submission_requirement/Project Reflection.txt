Project Reflection
One important design decision I made was integrating the Amazon Bedrock AgentCore Gateway with both API Gateway and AWS Lambda functions rather than embedding order tracking and refund logic directly into the agent. I exposed the order-tracker Lambda through API Gateway and connected both the order-tracking and refund-processing capabilities through the AgentCore Gateway. This separation of concerns makes the architecture more modular and maintainable. The agent focuses on reasoning and orchestration, while the Lambda functions handle business operations such as retrieving order status and processing refunds. This approach also makes it easier to update backend functionality without changing the agent logic.
One significant challenge I encountered was deploying the agent with the Bedrock AgentCore Starter Toolkit. During deployment, the process repeatedly failed because of dependency-resolution issues involving the pywin32 package, which is only available for Windows but was being evaluated during the Linux ARM deployment build. Earlier in the project, I also encountered issues with Windows Smart App Control blocking Python executables inside the virtual environment, and the AgentCore tooling required a ZIP utility that was not initially available on my system. I resolved these challenges by rebuilding my virtual environment, disabling Smart App Control, creating a local ZIP wrapper to satisfy the deployment prerequisites, and troubleshooting the dependency tree to identify the package causing the deployment failure. I also disabled OpenTelemetry observability after discovering it was preventing the runtime from starting successfully.
For a production deployment, security would be a major consideration. In this project, the AgentCore Gateway used a NONE authorizer for simplicity, but this would be inappropriate in a real customer-support system. A production implementation should use IAM authentication or OAuth-based authorization to protect customer order data. I would also apply least-privilege IAM policies so that Lambda functions and the deployed agent can access only the resources they require. Additionally, I would implement CloudWatch monitoring and logging to track agent performance, troubleshoot failures, and monitor operational costs. These measures would improve security, reliability, and maintainability while supporting growth in usage and customer traffic.
